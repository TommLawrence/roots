# Longview — The Long View

An agentic AI that follows one learner across **years, not one term** — surfacing sourced
strengths and struggles early enough for a teacher to open a real conversation with a family.

**Track:** Education — Longitudinal strength tracking
(Agentic AI for Africa Innovation Challenge)

Longview ingests the records a public school already has — quiz scores, assignment results,
attendance registers, teacher notes — and turns them into a **running, cited learner profile**.
Every strength or weakness it claims carries the exact quiz, term, and score it came from.
It never assigns a track, never labels a child, and never shares anything outside the
classroom without a named human approving it first.

## The one rule (enforced in code, not prompts)

A profile entry **cannot be written without at least one evidence reference**.
`update_profile` validates every evidence id against the raw records database and refuses
unsourced claims. An unsourced label on a child is worse than no label at all.

## Architecture in one breath

```
raw records (SQLite, messy on purpose)
        │
        ▼
Longview MCP server (ours: 9 domain tools — ingest, cited profile updates,
        flag_pattern, draft_summary, approvals, share gate)
        +   official sqlite MCP server (borrowed: generic read-only SQL)  ← why: audited, standard, zero code to maintain
        +   official filesystem MCP server (borrowed: sandboxed reads of records_inbox/)  ← why: school files stay outside our attack surface
        │
        ▼
LangGraph agent (plan → ingest → analyse → propose → HUMAN GATE → draft → finalize)
        │                                    ▲
        ▼                                    │ named human approves
teacher review UI (approve / dismiss flags) ─┘
        │
        ▼
audit log: every tool call, inputs, outputs, timestamps, approver
```

## Quickstart (one command after clone)

```bash
pip install -e ".[dev]" && make demo
```

`make demo` does the whole loop on synthetic data:

1. generates a messy 4-year synthetic cohort (80 learners, ~12 terms),
2. runs the agent end-to-end on one learner (tool calls logged to console + audit table),
3. starts the teacher review UI at http://localhost:8080.

## Running the open-weights model

Longview's full draft-summary task runs on an **open-weights model served locally**:

```bash
ollama pull qwen2.5:3b-instruct-q4_K_M   # ~2.0 GB RAM footprint
cp .env.example .env
```

Why 3B: the whole system is designed to run on modest hardware (8 GB RAM laptop).
The LLM layer is provider-pluggable — point `LONGVIEW_LLM_BASE_URL` at any
OpenAI-compatible endpoint to show a frontier model side-by-side in the demo video.

No Ollama installed? Everything still runs: the summary tool falls back to a deterministic
template drafter so the pipeline is always demonstrable.

## Repo map

| Path | What it is |
|---|---|
| `datagen/` | Synthetic cohort generator — realistically messy (missing rows, late entries, typos, attendance gaps) |
| `longview_mcp/` | **Our MCP server.** Tool logic lives in `core.py` (pure stdlib), FastMCP wrapper in `server.py` |
| `agent/` | LangGraph agent + CLI runner (`python -m agent.run --learner L003`; `--from-inbox` picks up school exports) |
| `records_inbox/` | Where the school drops term exports / scans; read **only** via the borrowed filesystem MCP server |
| `mcp_config.json` | Ready-made client config wiring all three MCP servers (ours + 2 borrowed) |
| `borrowed/` | The two MCP servers we did **not** write (official sqlite + filesystem) and why we borrow them |
| `ui/` | Teacher review UI (FastAPI) — dashboard, cited learner profiles, the share gate, evidence drill-down, audit log. The human gate, visible |
| `evals/` | 10+ test tasks, runner, honest pass/fail report incl. one known failure |
| `convex/` | Production backend (Convex): schema, **write functions that enforce the citation rule + human gate**, migrations, and an `/api/v1/*` HTTP bridge for the Python agent |
| `tests/` | Citation integrity, pattern detection, approval gate, audit completeness |
| `docs/` | Teacher interview notes (classroom fit), demo video script |

## Evals

```bash
make evals          # runs 10+ tasks x 3 repetitions, writes evals/results/EVALS_REPORT.md
```

`EVALS.md` is regenerated from the runner output — pass/fail per task, run-to-run
variation, and one failure we did **not** fix, with what we would try next.

## Data conduct

All data in this repository is **synthetic**, generated by `datagen/`. No real learner
records are used anywhere. The generator is deliberately messy — inconsistent note
quality, gaps in attendance, results logged late — because clean data lies.
